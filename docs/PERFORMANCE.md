# 성능 측정 기록

## 2026-10-16 웹폰트 정리

### 문제

2026-10-15 라이브 사이트를 Lighthouse 모바일로 재 보니 홈·앰프 상세 모두 성능 68점(3회 모두 같은 점수)이었다.
첫 화면 표시(FCP)와 가장 큰 요소 표시(LCP)가 모두 5.1초였고 스크립트 차단 시간(TBT)은 0ms였다.

- `fonts.googleapis.com`의 폰트 CSS 한 줄이 렌더링을 막고 있었다 (Lighthouse 추정 약 1.4초).
- 그 CSS가 Anton, Montserrat 4굵기, Noto Sans KR 4굵기를 불러왔고, 한글 본문 글꼴은 유니코드 조각 단위라
  홈에서만 폰트 파일 16개, 284KB를 받았다.
- 실제로 쓰지 않는 굵기도 있었다. Montserrat 600과 Noto Sans KR 800은 어느 요소에도 쓰이지 않았다.
- 한글 제목은 Montserrat에 한글이 없어 이미 시스템 글꼴로 표시되고 있었다. 한글 웹폰트는 본문에만 쓰였다.

### 바꾼 것

- 구글 폰트 CSS와 preconnect를 다섯 페이지에서 모두 제거
- 영문 제목용 Anton(18KB)과 Montserrat 가변 500–800(37KB)의 라틴 서브셋을 `fonts/`에 직접 호스팅.
  `npm run fonts`(`scripts/fetch-fonts.mjs`)로 다시 받을 수 있고, SIL OFL 1.1 라이선스를 함께 둔다.
- 한글은 `--font-system` 스택(Apple SD Gothic Neo, 맑은 고딕, Noto Sans KR(설치된 경우), system-ui)으로 표시.
  한글 본문의 글자 모양이 Noto Sans KR에서 기기 기본 고딕으로 바뀐다. 영문 제목과 레이아웃은 그대로다.

### 결과

같은 PC의 같은 로컬 정적 서버에서 전후를 쟀다. Lighthouse 13.5 모바일 기본 프리셋(시뮬레이션 스로틀링),
페이지당 3회 측정의 중앙값이다. 측정 PC의 CPU 지수(benchmarkIndex)는 회차마다 약 920–3,460으로 흔들렸다.

가로 넘침과 한글 단어 중간 끊김이 없는 것을 확인했다.

### 아직 하지 않은 것
